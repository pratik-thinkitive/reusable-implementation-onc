# Compliance & Security Map

**Domain: healthcare / PHI.** The service fetches and emits patient demographics, encounters, insurance coverage, diagnoses, medications, and clinical assessments, and now **persists patient identity and access decisions** to PostgreSQL. HIPAA Security Rule safeguards apply to every endpoint.

## Access Control & PHI Exposure
| # | Severity | Location | Issue | Fix |
|---|---|---|---|---|
| 6 | **Critical** | all three controllers | **No authentication or authorization anywhere.** Spring Security is not a dependency. Any caller who can reach the port reads full PHI for an arbitrary `fhirId`, or bulk-exports via `POST /ehr/cms/qrda/zip`. Violates HIPAA §164.312(a). | Add `spring-boot-starter-security` + OAuth2 resource server |
| 7 | **Critical** | [G2Controller.java:33](src/main/java/com/onc/G2/controller/G2Controller.java#L33) | The G2 access check is keyed on the **`fhirId` in the query string**, not on an authenticated principal. The whole access-request feature is therefore advisory: an unauthenticated caller passing any patient's id gets that patient's details as soon as *anyone* has granted access for them. | Derive the patient identity from the token; `fhirId` must never be caller-supplied here |
| 8 | **Critical** | [PatientAccessAdminController.java:90,97](src/main/java/com/onc/G2/controller/PatientAccessAdminController.java#L90) | `grant-access` / `revoke-access` are unauthenticated `POST`s taking only a request id — anyone can grant themselves access and move the measure numerator. | Require an authenticated admin role |
| 9 | **Critical** | whole service | **No audit logging.** HIPAA §164.312(b) requires recording who accessed which patient's record and when. `PatientAccessRequest` records *decisions*, not *accesses*; there is no actor identity or correlation id anywhere. | Emit a structured audit event (actor, patientId, endpoint, timestamp, outcome) on every PHI read |
| 10 | ~~High~~ **FIXED** | `PatientAttributionServiceImpl` | Patient **first and last name** and the **TIN** were written to application logs at INFO on every access request. | **Resolved 2026-08-25** — the lookup now logs organisation and provider ids plus whether a TIN was found; names and TIN values are gone. `fhirId` is still logged at INFO throughout G2. |
| 11 | ~~High~~ **FIXED** | `GlobalExceptionHandler` | `AccessOperationException` messages were built as `"Error granting access: " + e.getMessage()` and returned verbatim — JPA/SQL and upstream detail leaked into the response body. | **Resolved 2026-08-25** — unexpected failures now return a fixed sentence with the cause logged only, gated by `onc.expose-error-details` (default `false`, asserted by a test). Upstream status and body never reach the caller. |
| 12 | High | `RestTemplate` bean · `EHRTokenServiceImpl` | No connect/read timeout and no retry — a hung upstream blocks a servlet thread indefinitely. A fresh token is minted per API call (no cache, no `expires_in` handling), so every read is two round trips. | Configure timeouts on the bean; cache the token |
| 13 | Medium | `EHRDataServiceImpl` (`/medical-details`, `/personal-details`, `/insurance/cards`, `/doctor/`, `/clinic/`) | `patientId` is concatenated straight into upstream URLs with no encoding or format check. `fetchAppointments` and `fetchAllDoctorsByClinicId` already use `UriComponentsBuilder`; the rest do not. *Partly mitigated 2026-08-25 — a `fhirId` with no dash is now rejected with a 400 before any URL is built, but the extracted segment is still unencoded.* | Use `UriComponentsBuilder` everywhere; validate the id shape |
| 14 | Medium | admin listing + dashboard endpoints | Every listing is unpaginated and every dashboard loads all matching rows into memory before summing. `POST /ehr/cms/qrda/zip` takes an unbounded id list and buffers the whole ZIP. | Paginate; cap the ZIP request |

## Test Coverage
41 tests, all passing — but **entirely G2 controller slices with mocked services**. Uncovered: every EHR and QRDA class, all JPA repository queries (including the inconsistent predicates in #15/#18), the transaction boundaries in #20, CDA generation, `isInInitialPopulation`, terminology mapping, date conversion, and the regex XML patch. For a CMS submission artifact, generated documents should be validated against the CMS QRDA Cat I schematron in CI.

The response envelope and error contract are covered by `EnvelopeContractTest` and `VerboseErrorDetailsTest`, including the `ProblemDetail` guard and the assertion that a 500 never echoes its cause.

## Not Applicable / Not Found
- No PCI-DSS scope. Insurance payer/plan data is PHI, not cardholder data.
- No consent-management or break-glass logic. G2's access requests are a *measure* mechanism, not a consent framework — they gate one endpoint and are not consulted by EHR or QRDA.
- Encryption at rest now applies: PHI (names, patient ids, access history) is persisted to PostgreSQL. Neither TLS to the database nor disk encryption is configured in this repo.
